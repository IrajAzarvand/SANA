# سیاست پایان قرارداد و دسترسی مشتری در SANA

## قاعده دسترسی

- مدیر کل سامانه (site_admin) از کنترل انقضای قرارداد مشتریان مستثنا است.
- کاربر شخصی فقط زمانی اجازه ورود دارد که حساب او فعال باشد و حداقل یک قرارداد شخصی با وضعیت ذخیره‌شده active وجود داشته باشد که تاریخ شروع آن رسیده و تاریخ پایان آن امروز یا بعد از امروز باشد.
- مدیر سازمان و تمام کاربران وابسته به همان سازمان، از جمله کاربران شعب، تابع قرارداد معتبر سازمان هستند. پایان قرارداد سازمان دسترسی همه این حساب‌ها را می‌بندد.
- سازمانی که وضعیت آن غیر از active باشد نیز نمی‌تواند وارد سامانه شود.
- تاریخ پایان قرارداد شامل همان روز است؛ دسترسی از روز بعد از end_date قطع می‌شود. قراردادهای suspended یا cancelled حتی اگر تاریخ پایانشان نرسیده باشد، دسترسی ایجاد نمی‌کنند.
- وجود یک قرارداد معتبر دیگر برای همان مشتری می‌تواند دسترسی را حفظ کند؛ بررسی بر اساس وجود قرارداد معتبر انجام می‌شود، نه صرفاً آخرین قرارداد ایجادشده.

## اعمال کنترل در احراز هویت

1. ورود با نام کاربری/رمز عبور وضعیت قرارداد و سازمان را بررسی می‌کند.
2. احراز هویت JWT در هر درخواست محافظت‌شده دوباره وضعیت دسترسی کاربر را بررسی می‌کند؛ در نتیجه توکن دسترسی صادرشده پیش از انقضای قرارداد، پس از انقضا برای API قابل استفاده نیست.
3. endpoint تمدید JWT نیز قرارداد و وضعیت کاربر را بررسی می‌کند و برای حسابی که دسترسی‌اش منقضی شده توکن تازه صادر نمی‌کند.
4. این کنترل در بک‌اند است و به محدودیت‌های رابط کاربری وابسته نیست؛ درخواست مستقیم API نیز مسدود می‌شود.
5. این سیاست دسترسی به سایت را کنترل می‌کند؛ به‌تنهایی قرارداد دستگاه یا دریافت تله‌متری GPS را حذف نمی‌کند و داده‌های تاریخی دستگاه را پاک نمی‌کند.

## تست‌های مورد انتظار

- قرارداد سازمانی منقضی‌شده، توکن دسترسی قبلی مدیر سازمان و توکن تمدید او را بی‌اعتبار کند.
- قرارداد شخصی منقضی‌شده، درخواست API را مسدود کند.
- تاریخ پایان امروز همچنان معتبر باشد؛ روز بعد دسترسی قطع شود.
- مدیر کل سامانه مستقل از قرارداد مشتریان باقی بماند.
- مدیر شعبه نیز چون به سازمان متصل است، از همان وضعیت قرارداد سازمان پیروی کند.
